# Wine video dependency coverage

Fantastic Contraption’s 19 October 2026 headset runtime log repeatedly reported that its OVRPlugin could not load `MSVFW32.dll`, `AVIFIL32.dll` and `AVICAP32.dll`. The ARM64EC guest resource recipe now builds those three genuine modules from the same pinned Madeira/Wine source as the existing guest runtime. They must pass through the normal guest staging and asset receipt process; do not copy replacement DLLs into a previously verified app or reuse old resource receipts for changed contents.

The isolated compile used the pinned `a4af9f0c31b3cf54b426e430116b6a8958007943` Wine source and LLVM-MinGW 20260421 toolchain, with at most four jobs. The outputs have raw PE machine `0x8664` and valid CHPE version 2 metadata, identifying ARM64EC binaries. Static checks resolved all 250 direct mandatory/delay imported symbols from the three new DLLs and 9,215 symbols across their recursive import/forwarder closure against the existing r19 guest farm, with no missing providers or symbols. The external compile and audit receipts are under `/Volumes/XRDev/build/WineVisionVR/video-oct19/` and are development evidence, not a portable dependency.

This change supplies video API providers. It does not prove that every video codec or capture device works, and the isolated check did not execute the game, rebuild the native runtime, package or deploy an app. Fantastic Contraption also reported JIT pool exhaustion; adding these DLLs does not by itself establish a fix for that separate failure. A newly staged and signed build still needs a headset launch and sustained gameplay test.
